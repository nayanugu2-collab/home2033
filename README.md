# 2033 HOME · 부동산 갈아타기 실거래 모니터

동천센트럴자이 **전용 59㎡급의 최근 10건 평균 실거래가**와 관심 아파트의 가격 격차를 추적하는 정적 대시보드입니다. 최초 매수가 **11.2억원은 참고 정보**로만 표시합니다. HTML·CSS·JavaScript, Python 표준 라이브러리, JSON, GitHub Actions·Pages만 사용하며 별도 서버·DB·유료 API는 필요하지 않습니다.

저장소에는 GitHub Actions가 공식 API로 수집한 거래가 포함되어 있습니다. 최신 건수와 수집 시각은 data/trades.json과 사이트에서 확인할 수 있습니다. 이후 수집에 실패해도 마지막 정상 데이터를 볼 수 있습니다. **샘플로 둘러보기**를 누르면 별도의 가상 데이터로 UI를 확인할 수 있습니다. 샘플은 실거래나 미래 가격 예측이 아닙니다.

**[대시보드 열기](https://nayanugu2-collab.github.io/home2033/)** · [첫 수집·배포 성공 기록](https://github.com/nayanugu2-collab/home2033/actions/runs/40487250861)

운영 저장소는 [nayanugu2-collab/home2033](https://github.com/nayanugu2-collab/home2033)입니다. Secret 연결, 공식 수집, Pages 배포를 완료했으며, 아래 설정으로 관리합니다.

- [API Secret 설정](https://github.com/nayanugu2-collab/home2033/settings/secrets/actions): 이름은 **MOLIT_SERVICE_KEY**, 값은 발급받은 인증키입니다. 같은 이름이 이미 있으면 중복 등록하지 않습니다.
- [Pages 설정](https://github.com/nayanugu2-collab/home2033/settings/pages): **Build and deployment → Source → GitHub Actions**를 선택합니다.
- [수집·배포 실행](https://github.com/nayanugu2-collab/home2033/actions/workflows/update.yml): **Run workflow → main → Run workflow**로 수동 실행합니다. 매일 07:17 한국시간에도 자동 실행을 시도합니다.

설정 화면은 저장소 소유 계정으로 로그인해야 열립니다. 이 저장소는 이미 배포되어 있으므로 처음 설치하는 다른 저장소에만 아래 설치 절차를 적용하면 됩니다. 운영 중에는 Actions의 배포 성공 여부와 사이트의 최종 정상 갱신일을 확인하세요.

- 지역별 78개 관심·안내 단지(기준 단지를 포함하면 79개), 검색, 가격 격차 순위. 이 중 봇들5·6은 국민임대 안내용이며 매매 비교에서 제외합니다.
- 전용 59·74·84㎡급 필터, 상세 화면의 정확한 전용면적 타입 선택
- 단지별 건축연도·경과 연수(현재 한국 연도 − 국토부 공식 거래의 건축연도). 동별 연도가 다르면 범위로 표시하고, 자료가 없으면 확인 필요로 표시합니다. 면적 필터 및 샘플 가격과 무관하게 공식 건축연도만 사용합니다.
- 최근 10건 산술평균(기본값), 최근 거래 1건, 최근 3개월·6개월 거래 중앙값, 거래일·표본 수·배율
- 실거래가 월별 중앙값 및 같은 계약월의 기준 주택 대비 격차 그래프
- 최근 10건의 거래 내역과 월별 표본 표
- 2033년 기본 목표의 매도·부채·가족 차입금·자산·저축·성과급·대출·비용 계산
- 아이폰 폭에서 단지별 카드 목록, 브라우저에만 저장되는 계산기 입력

기존 중첩 폴더를 정리해 **이 README와 index.html이 있는 위치를 GitHub 저장소 루트**로 구성했습니다. 이 폴더를 다시 하위 폴더에 넣으면 Actions가 인식하지 않습니다.

## 1. GitHub 저장소 만들고 파일 올리기

1. [GitHub](https://github.com/)에 가입하고 로그인합니다.
2. 우측 상단 **+ → New repository**를 누릅니다.
3. 저장소 이름(예: **home2033**)을 정하고 **Public**을 선택한 다음 생성합니다. GitHub Free의 공개 저장소와 Pages를 사용하는 구성입니다.
4. 기본 브랜치는 **main**으로 사용합니다. 다른 이름을 쓰면 두 워크플로의 branch 설정도 수정해야 합니다.
5. 아래 파일과 폴더를 저장소 **루트**에 올립니다. 특히 숨김 폴더 **.github**가 빠지지 않게 확인합니다.

~~~text
home2033/
├── index.html
├── README.md
├── .nojekyll
├── .gitignore
├── package.json
├── assets/
│   ├── app.js
│   ├── core.js
│   ├── styles.css
│   └── favicon.svg
├── data/
│   ├── complexes.json
│   ├── trades.json
│   ├── status.json

│   └── generate_sample.py

    ├── update.yml
    └── test.yml
~~~

초보자는 GitHub Desktop에서 **File → Add local repository**를 선택하고 이 폴더가 저장소가 아니라는 안내가 나오면 **Create a repository here**로 생성한 뒤 커밋하고 **Publish repository**를 이용할 수 있습니다. 먼저 만든 온라인 저장소를 이용하려면 그 저장소를 clone하고 위 파일들을 복사해서 커밋·push합니다. 이미 파일이 있는 폴더에 다시 clone해서 하위 폴더를 만들지 않도록 주의하세요.

Git 사용에 익숙하다면 이 폴더에서 다음 명령을 실행합니다. 사용자명과 저장소명은 본인 것으로 바꾸세요.

~~~powershell
git init -b main
git add .
git commit -m "Build 2033 apartment dashboard"
git remote add origin https://github.com/사용자명/home2033.git
git push -u origin main
~~~

위 명령은 빈 원격 저장소 기준입니다. 기존 원격 이력이 있으면 clone 방식을 사용하세요.

## 2. 국토교통부 API 키 발급

1. [공공데이터포털의 국토교통부_아파트 매매 실거래가 상세 자료](https://www.data.go.kr/data/15126468/openapi.do)에 접속해 로그인합니다.
2. **활용신청**을 누르고 개발계정 신청을 완료합니다. 일반 매매 자료가 아닌 **상세 자료** 서비스입니다.
3. 마이페이지의 활용신청 현황에서 승인 상태를 확인합니다.
4. **일반 인증키(Decoding)**를 복사합니다. 키 활성화에 시간이 걸릴 수 있습니다.
5. 아래 Secrets에만 등록합니다. HTML·Python·JSON·README·Git 커밋에 키를 붙여 넣지 않습니다.

수집 URL:

~~~text
https://apis.data.go.kr/1613000/RTMSDataSvcAptTradeDev/getRTMSDataSvcAptTradeDev
~~~

[공식 API 안내](https://www.data.go.kr/data/15126468/openapi.do)는 지역코드(법정동 앞 5자리)와 계약년월로 조회하는 XML 서비스입니다. 수집기는 응답의 법정동 뒷 5자리와 법정동명, 주소도 확인합니다.

## 3. GitHub Secrets에 키 등록

저장소에서 다음 메뉴로 이동합니다.

**Settings → Secrets and variables → Actions → New repository secret**

- Name: **MOLIT_SERVICE_KEY**
- Secret: 발급받은 **Decoding 인증키**

**Add secret**을 누릅니다. 키를 변경할 때도 같은 이름의 Secret을 수정합니다. 로컬 개발에서는 환경변수로만 전달하며, .env 자동 로딩 기능은 없습니다.

## 4. GitHub Pages 활성화

**Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택합니다.

이 프로젝트는 **Deploy from a branch를 사용하지 않습니다.** 데이터 수집과 Pages 배포를 같은 워크플로에서 직접 수행합니다. 기본 GITHUB_TOKEN으로 만든 커밋은 다른 push 워크플로를 실행하지 않으므로, 별도의 배포 실행에 기대지 않는 구조입니다. [GitHub 공식 토큰 설명](https://docs.github.com/en/actions/concepts/security/github_token), [Pages 배포 워크플로 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

저장소 **Settings → Actions → General**에서 Actions가 허용되어 있는지 확인합니다. 워크플로 파일은 contents: write, pages: write, id-token: write를 요청합니다. 조직 정책이나 보호된 main 브랜치가 봇의 데이터 커밋을 막으면 정책에 맞는 예외 설정이 필요합니다.

## 5. 첫 수집과 배포 실행

1. 저장소의 **Actions** 탭을 엽니다.
2. 왼쪽에서 **Update trades and deploy Pages**를 선택합니다.
3. **Run workflow → Branch: main → Run workflow**를 누릅니다.
4. 실행 목록에서 각 단계의 결과를 확인합니다.
5. 성공하면 data/trades.json이 공식 실거래로 갱신되고 data/status.json에 수집 성공이 기록됩니다.
6. **Deploy latest data directly** 단계 또는 **Settings → Pages**에 나온 주소를 엽니다.

~~~text
https://사용자명.github.io/home2033/
~~~

첫 push는 Secret/Pages 설정이 끝나기 전에 실행될 수 있습니다. 위 설정을 마친 후 수동으로 다시 실행하면 됩니다. 수집 실패 시에도 기존 가격과 오류 안내를 배포한 뒤 워크플로를 실패로 표시합니다. **빨간 실행 표시가 있어도 마지막 정상 사이트는 열릴 수 있습니다.** 어느 단계가 실패했는지 로그를 확인하세요.

아이폰 Safari에서 사이트를 열고 **공유 → 홈 화면에 추가**를 선택하면 편하게 사용할 수 있습니다. 실제 웹 사용 시에는 Pages의 HTTPS 주소를 이용합니다.

## 6. 매일 자동 갱신

- 매일 **07:17 한국시간**(전날 UTC 22:17)에 수집을 시도합니다.
- 최근 12개월의 계약일을 저장합니다. 예: 2026-10-26 실행이면 **2025-10-27~2026-10-26**.

- 지역별 페이지를 끝까지 조회하고 누락·중복 페이지·응답 건수 변경을 검사합니다.
- 요청은 최대 3회 재시도합니다. 어느 한 지역·월이라도 실패하면 가격 파일을 바꾸지 않습니다.
- 정상 데이터는 임시 파일에 완성한 뒤 파일 교체로 저장합니다. 실패 상태는 별도 status.json에 기록합니다.
- 일부 시군구의 정상적인 거래 0건은 허용합니다. 전 시군구·월이 모두 0건이면 비정상 응답 가능성으로 기존 가격을 보존합니다.
- GitHub 예약 실행은 지연될 수 있습니다. 사이트의 **최종 정상 갱신**과 Actions 실행 기록을 확인하세요. 공개 저장소는 장기 비활성 상태에서 예약 작업이 중지될 수 있으므로 GitHub 안내에 따라 다시 활성화합니다.

## 데이터와 계산 기준

### 단지 확인

[data/complexes.json](data/complexes.json)에 후보의 ID, 10자리 법정동 코드, 법정동명, 지번, 세대수, 허용한 정확한 단지명 별칭, 검증일·출처를 관리합니다. [전체 검증 기록](docs/registry-review.md)을 함께 확인하세요.

- 이름의 부분 문자열로 매칭하지 않습니다.
- 시군구 코드 + 법정동 코드 + 법정동명 + 명시적 별칭 + 주소가 일치해야 합니다.
- 정상 지번이 있으면 등록된 지번과 일치해야 합니다. 다른 지번을 같은 도로명으로 느슨하게 연결하지 않습니다.
- BL- 등의 지번 공란·블록 표기, 명시된 구 지번에 한해 검증된 도로명과 건물 본번·부번까지 일치하면 허용합니다.
- 어느 단지인지 유일하게 결정되지 않으면 제외합니다. 등록되지 않은 별칭은 추측해서 연결하지 않습니다.
- 해당 지역의 모든 500세대 이상 아파트를 전수 수록한 목록은 아닙니다. 기존 관심 후보를 보존하고, 2026-10-27 판교·서현 주변 27개 단지를 추가했습니다.
- 판교·삼평(봇들1·2·3·4·5·6·7·9), 판교·백현(기존 백현2 + 백현5·알파리움2·그랑블·더샵), 서판교(판교원5·7·9·11 및 산운11·12·13), 서현(시범4개 관리단지와 효자촌5개 관리단지)으로 찾을 수 있습니다. 검색은 띄어쓰기와 별칭도 처리합니다.
- 봇들5·6은 LH 국민임대 단지입니다. 명부에는 남기되 매매 가격·격차·배율·그래프·매수 계산을 제공하지 않습니다. 임대료나 인근 가격으로 대체하지 않습니다.
- 삼성·한신은 K-apt 관리단지 1,781세대 하나로, 효자촌 그린타운(대우·럭키·화성)은 1,774세대 하나로 집계합니다. 해당 단지의 승인된 API 별칭만 포함하며 중복 후보를 만들지 않습니다.
- 단지 정보는 K-apt 공개 기본정보와 KB·LH 자료로 대조했습니다. 일부 K-apt 출처는 2018년 관리비 공개 목록의 단지 기본정보이므로 출처 라벨에 그 기준을 명시했습니다. 법정동·지번·거래 명칭은 별도로 공식 실거래 XML과 확인합니다.
- 세대수는 관리·분양 단지 기준입니다. 임대 포함 소개 자료와 차이가 있는 단지는 메모를 남깁니다.
- ‘이수’는 이수역 생활권으로 취급합니다. 별도의 ‘이수동’ 법정동 코드는 만들지 않습니다.
- 인터넷 공개 단지정보를 대조한 것이며 정부의 공인 검증을 의미하지 않습니다. 실제 API 연결 후 이름·필지 변경이 발견되면 근거를 확인한 뒤 명부와 출처를 같이 갱신해야 합니다.

### 전용면적과 가격

| 필터 | 포함 전용면적 |
|---|---|
| 59㎡급 | 58 이상 60 미만 |
| 74㎡급 | 73 이상 75 미만 |
| 84㎡급 | 83 이상 85.01 미만 |

77㎡를 74㎡에, 81㎡를 84㎡에 섞지 않습니다. 필터는 공급평형이 아닙니다. 한 면적급의 서로 다른 타입은 함께 집계될 수 있으며 상세의 **전용면적 타입**에서 실제 소수점 면적까지 구분할 수 있습니다. 필터 밖의 면적도 수집 JSON에는 보존하지만 비교 화면에서는 사용하지 않습니다.

- 기본 기준 가격 = 최근 12개월 동천센트럴자이 59㎡급의 최신 최대 10건 산술평균
- 후보도 선택 단지·면적의 최신 최대 10건을 평균합니다. 상세의 정확한 전용면적 선택도 평균에 적용됩니다. 표본은 가상 샘플이 아닌 실제 거래입니다.
- 10건 미만이면 있는 거래만 평균하고 사용 건수·계약일 범위를 표시합니다. 거래가 없으면 값을 비우며, 두 단지의 표본 기간은 다를 수 있습니다. 3건 미만은 ‘거래 부족’입니다.
- 차액(억) = (후보 선택 가격(만원) − 기준 가격(만원)) / 10,000
- 배율 = 후보 선택 가격 / 기준 가격
- ‘최근 거래 1건’이나 후보 중앙값을 선택하면 기존 방식대로 기준 가격은 최신 1건입니다. ‘최근 10건 평균’으로 돌아오면 양쪽 모두 평균을 사용합니다.
- 중앙값은 최근 N건이 아닌 **달력상 최근 3·6개월** 거래 전체의 중앙값입니다.
- 짝수 건은 가운데 두 금액의 평균입니다. 표본 1~2건이면 값과 함께 **거래 부족**을 표시합니다.
- 같은 계약일은 거래 ID 사전순으로 정렬합니다. 첫 건을 ‘최근 1건’으로 표시하고, 최근 10건의 경계도 같은 정렬로 결정합니다. 실제 당일 계약 순서를 뜻하지 않으며 상세에 동률 건수를 안내합니다.
- 기준 거래가 없으면 기준가·차액·배율을 비웁니다. 최초 매수가나 계산기의 예상 매도가로 대체하지 않습니다.
- 추세 그래프는 **월별 중앙값**입니다. 월별 두 단지 모두 거래가 있어야 격차를 계산하고, 없는 월은 선을 끊습니다.
- 동일하게 공개된 날짜·층·면적·가격의 계약이 여러 개일 수 있어 임의로 중복 제거하지 않습니다.
- 표시 금액은 소수점 둘째 자리로 반올림하며 내부 계산은 원본 만원 단위를 사용합니다.
- 일부 낮은 가격의 직거래도 API 정상 신고 거래라면 포함됩니다. 상세 내역의 거래유형을 확인하세요.

### 자금 계획

모든 부채·저축·성과급·신규 대출·비용은 개인 상황을 추측하지 않고 **0부터 시작**합니다. 매도가는 선택한 기준 가격(기본 최근 10건 평균)에, 목표 매수가는 선택 단지의 비교 가격에 연동되며 직접 수정할 수 있습니다. 직접 입력한 예상 매도가는 비교 가격을 바꿔도 유지합니다. 두 값은 **미래의 가정값**으로 실제 시세 비교와 구분합니다.

~~~text
매도 순자금 = 예상 매도가 − 주담대 잔액 − 가족 차입금 잔액
추가 저축(억) = (월 저축액(만원) × 남은 개월 + 연간 성과급(만원) × 횟수) / 10,000
자기자본 = 매도 순자금 + 금융자산 + 추가 저축
조달 가능액 = 자기자본 + 신규 주담대
총 필요액 = 목표 매수가 + 취득세 예상액 + 기타 거래비용
추가 필요 자기자본 = max(0, 총 필요액 − 조달 가능액)
~~~

월 저축은 다음 달부터 목표 월까지, 성과급은 12개월을 채울 때마다 한 번 적립하는 단순 가정입니다. 예: 2026-10부터 2033-12까지 86개월, 성과급 7회. 투자가치 상승·부채의 월별 자동 상환·이자·소득세·미래 주택가격·대출 한도·세율을 자동 예측하지 않습니다. 향후 상환 계획은 잔액·저축 입력에 직접 반영합니다. 취득세와 거래비용은 사용자가 예상 **금액**을 넣습니다.

입력값은 localStorage에만 저장합니다. 샘플 모드 입력은 저장하지 않으며 공식 모드로 돌아갈 때 기존 자금 입력을 복원합니다. 다른 기기와 동기화되지 않으며 브라우저 데이터를 지우면 사라집니다.

## 로컬 실행과 테스트

Python 3.12 이상과 Node.js 20 이상을 설치한 후 이 폴더에서 실행합니다. 유료 서비스나 npm 패키지 설치는 필요하지 않습니다.

~~~powershell
python -m http.server 8765 --bind 127.0.0.1
~~~

브라우저에서 **http://127.0.0.1:8765/** 를 엽니다. HTML을 파일 탐색기에서 더블클릭하면 JSON·모듈 fetch가 차단될 수 있으므로 HTTP 서버를 사용합니다.

~~~powershell
python -m unittest discover -s tests -p "test_*.py" -v
node --test tests/core.test.mjs
node --check assets/app.js
python scripts/build_site.py
~~~

빌드 결과는 **site/** 입니다. 빌더는 HTML·README·assets·data·docs·.nojekyll만 포함하며 수집 소스·환경변수·워크플로를 배포하지 않습니다. 이 폴더는 Git 추적 대상이 아닙니다. 샘플을 다시 만들려면 **python scripts/generate_sample.py**를 실행합니다. 실제 가격 파일은 변경하지 않습니다.

[검증 결과와 모바일 재현 절차](docs/validation.md)에서 수행한 테스트와 미검증 항목을 구분해 확인할 수 있습니다.

## 오류 해결

| 증상 | 확인 방법 |
|---|---|
| Actions 목록에 작업이 없음 | .github/workflows가 저장소 루트인지, main에 push했는지 확인 |
| API 수집 단계 실패 | Secret 이름, 상세 API 신청·승인, 키 활성화·일일 호출량 확인 |
| 이전 가격이 남음 | 정상 동작: 일부 요청 실패 시 보존. status.json과 마지막 정상 갱신일 확인 |
| 단지 가격만 비어 있음 | 해당 전용면적 거래 부족 또는 별칭·필지 변경 가능. 공식 공개시스템과 명부의 주소·코드 대조 |
| git push 권한 오류 | Actions 권한, 조직 정책, main 브랜치 보호 설정 확인 |
| Pages 배포 오류 | Pages Source가 GitHub Actions인지, github-pages 환경이 main 배포를 허용하는지 확인 |
| 사이트 404 | 설정 후 수동 재실행, 작업의 Deploy 단계와 Pages 주소 확인 |
| 모바일에서 예전 화면 | 새로고침 버튼 사용. 정상 갱신일과 실제 계약일을 따로 확인 |
| 예약 작업이 실행되지 않음 | GitHub 실행 지연·비활성 상태 확인 후 Run workflow로 수동 실행 |
