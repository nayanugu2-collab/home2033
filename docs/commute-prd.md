# 2033 HOME 출퇴근시간 점수 PRD

2026-11-21 · 단계별 실행 계획

매수가와 면적으로 추린 이사 후보를 삼성·판교·광화문·여의도 이동 편의성으로 비교한다. **아침 출근부터 검증·출시하고 저녁 퇴근은 역방향으로 따로 검증한다.** 지역별로 지하철·자차의 점수와 가중 시간을 표시한다. 상세 화면에서는 네 업무지 각각의 편도 시간, 기준 출입구, 집계 단지 수, 조회 기준을 확인할 수 있다.

## 1. 목적지와 가중치

|---|---:|---:|---|
| 삼성역 | 100 | 45.5% | 서울 2호선 삼성역, 코엑스 쪽의 운영 중인 출입구 또는 대체통로 지상 출구. 공사 안내 확인 후 고정 |
| 판교역 | 20 | 9.1% | 성남 분당구 판교역(신분당선·경강선) 1번 출구 |

출구 번호는 소요시간 수집 전에 지도와 운영기관 공지에서 위치와 이용 가능 여부를 대조한다. 자차 도착점은 같은 출구 인근의 합법적으로 진입 가능한 도로 또는 주차장 진입점으로 고정한다. 보행·차량 종점 이름과 좌표를 함께 저장하고 화면에 공개한다. 이용 출구나 차 진입점 변경 시 기준 버전을 바꾸고, 비교 대상 전부를 같은 기준으로 갱신한다. ### 점수 계산

- 목적지별 소요시간을 분으로 놓고, 같은 수단의 가중 시간 `W = (삼성×100 + 판교×20 + 광화문×50 + 여의도×50) ÷ 220`을 계산한다. 지하철과 자차는 별도로 계산한다. 퇴근도 같은 업무지 가중치를 적용해 방향별 점수를 각각 계산한다.
- 표시 점수는 `반올림(6000 ÷ (60 + W))`를 기본안으로 한다. 60분이 50점이고 이동시간이 짧을수록 높다. 순위는 반올림 전 가중 시간이 짧은 순으로 정한다. 점수 옆에 가중 시간을 함께 표시한다.
- 계산 예시로 네 목적지의 지하철 시간이 각각 40·25·50·45분이면 가중 42.0분, 59점이다. 같은 방식으로 자차 점수를 별도로 보여준다.
- 네 목적지 중 하나라도 계산이 불가능하면 해당 수단의 점수는 보류하고 개별 확인 시간과 상태를 표시한다. 경로 정보 없음과 수집 실패를 구분한다. 누락된 목적지의 비중을 다른 목적지에 배분하지 않는다.

## 2. 지역별 출발점

**단지마다 실제 출입구를 기준점으로 삼는다.** 출근 때 지하철은 단지 보행 정문, 자차는 차량 출입구에서 출발한다. 퇴근 때의 단지 도착점은 보행·차량 방향에 맞춰 확인한다. 국토부 실거래의 법정동·단지명·지번과 공식 도로명주소를 대조하고, 보행과 차량 출입구를 별도로 확인한다. 기준점이 하나만 확인되면 해당 수단만 표시할 수 있다. 역 이름은 출발지 대신 쓰지 않고, 계산된 경로에 실제 이용한 첫 승차역을 표시한다. [주소정보 출입구 좌표](https://business.juso.go.kr/jst/jstAddressCuration)

| 화면 범위 | 집계 방법 |
|---|---|
| 단지 | 해당 단지의 확인된 출입구에서 계산한 점수와 4개 역별 시간 |
| 법정동 | 동에 속한 계산 가능 단지의 가중 시간 중앙값으로 지역 점수 산출. 단지 수와 가중 시간 범위(최솟값~최댓값) 표시 |
| 분당·수지·동탄 전체, 서울 각 구 | 산하 동에서 포함한 단지를 한 번씩 모아 중앙값 계산. 같은 법정동이나 단지를 중복 집계하지 않는다. 동별 표본 수와 각 범위 표시 |
| 내 예산으로 지역 찾기 | 선택한 면적·가격 범위의 실제 거래 단지 중 출근시간이 확인된 단지만 집계. `시간 확인 단지 / 가격에 맞는 단지` 표시 |

초기에는 동별로 지하철역 접근성이 서로 다른 단지를 최대 3곳 고정한다. 주소가 확인된 후보를 운영 중인 역까지 직선거리로 정렬해 가까운 쪽·중간·먼 쪽을 하나씩 고른다. 직선거리는 표본 선정에만 쓰고, 화면의 소요시간은 실제 길찾기 경로로 계산한다. 표본 밖 단지는 별도 경로를 확보할 때 추가한다. 지역 상세에 표본 단지 이름을 공개하고, 집계 1~2개 단지는 `표본 적음`을 표시한다. 0개인 지역은 시간을 비워 둔다.

기존 명부로 시작할 때 사용할 **기준점 후보**는 아래와 같다. 역 이름은 그 지역에서 점검할 경로 후보이고, 같은 지역 안에서도 실제 선택 노선은 단지마다 달라질 수 있다.

| 비교 지역 | 출발점 후보 | 경로에서 확인할 역 후보 |
|---|---|---|
| 동천동·수지 | 동천센트럴자이 정문·차량 출입구. 수지 전체는 성복·풍덕천·상현 생활권 단지 추가 | 동천역·성복역·수지구청역·상현역 |
| 분당 정자동 | 파크뷰·상록마을 우성 등 정자동 단지 출입구 | 정자역·수내역 |
| 분당 서현동 | 시범단지 삼성한신과 효자촌 동아 등 출입구 | 서현역 및 실제 도보 승차역 |
| 판교·백현·삼평 | 백현마을 5·6·7단지, 봇들마을7단지 등 매매 대상 단지 출입구 | 판교역 및 실제 도보 승차역 |
| 서판교 | 판교원마을7단지와 운중동 산운마을 등 단지 출입구 | 철도 접근 가능 여부부터 확인하고 필요 시 버스+전철을 별도 표시 |
| 동탄 | 반송동 동탄1 생활권, 여울동 동탄역 생활권, 청계·산척·장지 생활권의 실거래 단지 출입구 | 동탄역 접근 경로와 실제 운영 중인 광역전철 |
| 서울 송파·강동 | 잠실엘스·헬리오시티, 고덕그라시움·올림픽파크포레온 등 서로 다른 생활권 단지 출입구 | 잠실·잠실새내·송파·고덕·둔촌동 일대 |
| 서울 성동·광진·동작·서초, 경기 과천 | 옥수파크힐스·신금호파크자이, 광장현대3단지, 아크로리버하임, 방배그랑자이, 과천자이 등 단지 출입구 | 옥수·신금호·광나루·흑석·방배·과천의 이용 경로 |

서울·경기부터 점수 검증을 시작한다. 부산·대구·대전의 예산 결과는 기존대로 제공하고, 수도권 지하철로 연결되지 않는 경우 `광역 이동`으로 안내한다. KTX·SRT와 연계한 장거리 경로 비교는 별도 시나리오로 검토한다.

## 3. 시간 측정 기준

| 항목 | 초기 설정 |
|---|---|
| 시간대 | 출근은 한국시간 기준 휴일이 아닌 화·수·목 오전 08:00에 단지에서 출발한다. 퇴근은 같은 기준 요일에 업무지에서 출발하며, 오후 18:30을 초기 검증 시각으로 둔다. 방향별로 날짜별 시간을 조회해 중앙값을 사용하고 조회일과 유효 표본 수를 표시한다 |
| 지하철 | 출발점에서 역까지 걷는 시간, 승차 대기, 철도 탑승, 환승과 하차 후 도착점까지의 보행을 포함한 전체 시간. 운영 중인 도시·광역전철 경로 중 도보+철도 경로를 선택. 버스+전철은 별도 라벨·점수로 제공할 수 있음 |
| 자차 | 같은 요일·시각의 교통을 반영한 추천 경로에서 방향별로 확정한 차량 출발점과 도착점 사이의 예상 분수. 유료도로 허용을 기본안으로 하고, 목적지 주차 탐색과 주차 후 도보는 별도 |
| 비교 경로 | 각 목적지·표본 시각별로 동일한 추천 경로 선택 정책을 사용. 지하철 공급사가 대기시간을 포함하는지 확인하고, 직접 계산하는 경우 실제 시간표로 대기·환승을 계산 |
| 데이터 미확인 | 경로 없음·자료 미수집·API 오류를 구분. 갱신 실패 시 이전 수치에 기준 날짜를 표시하고, 시간이 오래된 표본은 별도 안내 |

## 4. 단계별 실행 계획

### 1단계. 표본 단지와 업무지 기준점 확정

초기에는 기존 명부에서 지역별 한 곳씩 확인한다. 아래 ID는 실거래와 출퇴근 데이터를 연결할 때 사용한다.

| 표본 지역 | 단지 | 단지 ID | 법정동 코드 |
|---|---|---|---|
| 동천 | 동천센트럴자이 | `base` | `4146510300` |
| 분당 | 파크뷰 | `parkview` | `4113510300` |
| 판교 | 봇들마을7단지 | `botdeul7` | `4113510900` |
| 송파 | 잠실엘스 | `els` | `1171010100` |

각 단지의 보행 정문과 차량 출입구, 네 업무지의 보행 출구와 차량 진입점을 지도와 운영기관 자료로 확인한다. 산출물은 단지 ID·법정동 코드·출입구 이름·WGS84 좌표·출처·확인일을 담은 명부다. 어느 수단의 기준점이 미확인이면 해당 수단은 확보한 지점이 생길 때 조회한다.

현재 기준점 후보와 좌표 확인 상태는 단계별 확인 기록에서 관리한다. [기준점 명부](https://github.com/nayanugu2-collab/home2033/blob/main/data/commute/endpoints.json) · [확인 기록](commute-endpoint-verification.md)

### 2단계. 길찾기 공급사와 아침 표본 검증

- **지하철**. TMAP 대중교통의 경로 전체시간과 구간유형(`WALK`, `SUBWAY` 등), `searchDttm` 요청 시 실제 대기시간 반영 여부를 확인한다. ODsay의 지하철 경로를 대안으로 볼 수 있으며, 저장·가공·배포에 필요한 사전 동의 조건을 확인한다. 자체 계산을 검토할 경우 운행 시간표·환승 보행·역 출입구가 표본 경로를 덮는지 먼저 확인한다. [TMAP 대중교통 API](https://transit.tmapmobility.com/docs/routes) · [ODsay 경로 검색](https://lab.odsay.com/guide/releaseReference?platform=web) · [ODsay 이용약관](https://lab.odsay.com/doc/totalPolicy) · [국가철도공단 운행정보](https://www.data.go.kr/data/15013206/standard.do)
- **자차**. 카카오모빌리티 미래 운행 정보 API에서 실제 계정의 날짜·시각 조회 가능 여부, 응답 시간 단위, 08:00 교통 반영과 통행료 조건을 확인한다. 필요한 접근 권한이 없으면 직접 기록했거나 사용에 동의받은 표본으로만 경로를 대조한다. [카카오모빌리티 미래 길찾기](https://developers.kakaomobility.com/guide/navi-api/future) · [제공량과 가격](https://developers.kakaomobility.com/price/)
- 한 단지에서 네 업무지까지 같은 시각의 응답을 지도 경로와 먼저 대조하고, 통과한 수단을 네 단지의 화·수·목 표본으로 확대한다. 네 단지 × 네 업무지 × 사흘은 **방향당 수단별 48회**다. 두 수단의 출근은 96회, 출퇴근 두 방향까지는 192회가 기본 조회량이며 추가 요청과 재시도는 별도다.
- 산출물은 수단별 검증표다. 표본별 출발점·도착점·날짜·지정 시각, 도보·환승·교통 반영 여부, 비교 지도와의 차이, 계정 한도, 요약값 저장·공개 가능 범위를 기록한다. 실측 및 공개 조건을 확인한 수단부터 다음 단계에 올린다.

### 3단계. 점수와 집계 로직 구현

- 업무지마다 유효 표본의 편도 시간 중앙값을 구한 뒤, 네 값으로 수단별 가중 시간과 점수를 계산한다. 초 단위 응답은 분으로 환산하고, 순위에 사용할 원래 가중 시간은 표시용 점수 반올림과 함께 보존한다.
- 단지 ID·수단·방향·업무지·기준점 버전으로 데이터를 연결한다. 누락된 업무지가 있으면 개별 확인 시간과 상태를 내보내고 그 수단·방향의 합산 점수는 비워 둔다. 경로 없음, 미수집, 일시 오류를 기록한다.
- 계약 조건과 상관없이 같은 단지의 방향별 경로는 한 번 계산한다. 지역 비교는 해당 단지를 한 번씩 집계하고, 예산 결과는 현재 가격·면적 필터에 들어온 단지만 다시 집계한다. 테스트에는 가중치, 설명에 나온 예시, 결측, 동점, 지역·단지 중복 제거를 포함한다.

### 4단계. 아침 출근 점수 표시

- 단지 상세에 지하철·자차의 가중 시간과 점수, 네 업무지별 시간, 출발·도착 기준점, 조회일을 표시한다.
- 예산 검색의 `가격 상한 근접순`을 기본으로 두고 `지하철 출근순`과 `자차 출근순`을 추가한다. 각 정렬은 현재 가격·면적 조건으로 추린 후보 안에 적용한다. 점수가 없는 후보도 검색 결과에 표시하며, 출근순에서는 확인된 후보 다음에 배치한다. 지역 카드에 `시간 확인 단지 / 가격에 맞는 단지`를 표시한다.
- 지역 비교는 표본 수와 가중 시간 범위를 함께 보여준다. 모바일과 PC에서 필터 변경, 정렬, 자료가 없는 후보의 표시를 확인한 뒤 표본 지역에 배포한다.

### 5단계. 수집·갱신 운영

공급 조건이 허용하면 경로 요약 파일을 정적으로 배포하고 GitHub Actions에서 주 1회 갱신한다. 초기 수동 실행에서 호출량과 처리 시간을 확인한다. API 키는 Actions Secret에 두고 공개 파일에는 단지 ID, 허용된 시간 요약, 조회일, 방향, 기준점 버전과 출처를 담는다. 수집 실패 시 해당 경로의 마지막 정상 조회일을 표시한다. 출퇴근 갱신과 실거래 갱신은 각각의 결과를 기록한다.

### 6단계. 저녁 퇴근과 지역 확장

네 표본 단지로 업무지→단지의 보행·차량 진출입점을 확인하고, 오후 18:30을 후보로 지정 시각의 경로 응답과 교통 반영을 검증한다. 출근과 동일한 방식으로 퇴근 점수를 계산해 화면과 정렬에서 방향을 고를 수 있게 한다. 그다음 동천·분당·판교·송파의 표본을 동별 최대 3곳으로 넓히고, 수지의 다른 동·동탄·서울의 다른 구를 순차 검증한다.

## 5. 검수 기준

- 목적지별 가중치 합 220 적용. 삼성역 시간이 10분 늘면 가중 시간이 약 4.55분 늘고, 판교역 시간이 10분 늘면 약 0.91분 늘어난다.
- 지하철·자차는 같은 방향에서 동일한 비교 시각과 업무지를 사용한다. 방향별 개별 시간과 합산 점수를 대조하고, 지하철 경로는 걷기·환승·대기시간 포함 여부를 확인한다. 퇴근에는 역방향으로 따로 조회한 표본을 사용한다.
- 정자역과 떨어진 단지, 서판교 철도 미연결 경로, 동탄의 서로 다른 생활권, 서울 동남·서남권의 표본을 포함한다.
- 단지·법정동·시군구 집계가 정확하고, 예산을 바꾸면 집계에 포함되는 단지와 표본 수가 함께 바뀐다. 확인되지 않은 시간이나 점수는 표시하지 않는다.
- 앱에 넣기 전에 4개 역별 지하철·자차 시간을 동일한 출발점·시각의 공개 지도 경로와 표본 대조한다. 편차가 큰 경우 도보·환승·주차·정체·좌표의 차이를 확인한다.
